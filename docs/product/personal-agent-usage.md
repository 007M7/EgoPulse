# Personal Agent 使用方式

本页对应新增自然语言与返工入口的 `draft.24` 候选版本。安装包、daemon 和客户端须来自同一版本；旧版控制台不会因源码更新自动获得这些入口。

## 开始对话

先运行 `egopulse status` 检查连接，再运行 `egopulse-tui`。在主界面按 Enter 或 `i` 打开对话，输入中文后按 Enter 发送。问候会收到回复；信息不足时会提出澄清；明确的工作请求会产生待审核建议。

在 PowerShell 中使用一次性问答：

```powershell
egopulse ask "你好"
egopulse ask "请检查当前项目中的边界错误，说明建议修改的文件和验证方法"
```

PowerShell 的 `PS ...>` 提示符接收系统命令。要输入自然语言，请进入 TUI 对话或使用 `egopulse ask`。

## 从建议开始工作

建议出现后，在对话界面按 F4 将建议带入工作草稿。核对内容后按 Enter 准备，查看工作范围、材料、模型路线和限制，再确认执行。对话、澄清与建议本身不会创建执行任务。

执行中，在任务页查看状态和内容。需要命令审批时，到审批队列查看具体命令、目录和影响后作决定。完成后进入结果审核，查看产物和验证，再选择 Accept、Reject 或 Rework。

同一个原生执行实例忙碌时，后续任务等待可用容量，不会替换正在执行的任务。等待中的任务可以取消；系统核实执行尚未创建后，才会标记为已取消。已经开始执行的任务则等待原生取消结果。

## 选择执行能力

对话界面可查看实际配置的 Provider、Harness 和模型，使用上下键和 F2 选择本次可用路线；F3 设置以后工作的默认值。选择变化后需重新解释当前建议。已确认的任务继续使用其冻结路线。

只有显示可选的组合能够用于新工作。候选或挂起的组合会显示不可用原因。Codex 套餐登录与其他 Provider/API 凭证是不同的接入方式；现有登录不代表任意 Harness 都能使用该额度。

## 继续返工与记录经验

Rework 裁决应用后，返回任务页选择原任务，按 `f` 准备继续返工。核对继承的起始材料和返工要求，再按 Enter 确认。后续工作保留同一个任务身份。

任务页和结果审核页的 `m` 打开经验候选表单。填写内容、来源和范围；提交的记录只是候选，需经过接受流程才成为可检索的已接受 Memory。

## 遇到中断

“结果未知”表示尚不能确定操作是否提交。使用当前页面的精确重试或读取原任务，避免重新创建任务。返工确认会保存受保护的恢复记录；重开后可使用页面给出的文件路径：

```powershell
egopulse work recover-rework "恢复记录的完整路径" --json
```

恢复记录只能在原用户身份和同一数据存储下重放。它不会更新权限或重新生成工作。若模型会话在 daemon 重启后无法恢复，任务应明确进入挂起/对账状态；不能把旧“已派发”记录当作仍在执行的证明。

结果保存遇到临时数据库锁时，系统保留原结果并重试保存，不会重新调用模型。完整性错误仍会停止处理；进程重启后的结果不确定状态需要核对，不能当作任务成功。

这些入口的实现与实际闭环验收分别记录。仅出现连接成功或模型回复，不能证明任务执行、验证、裁决和恢复已经完成。
